All new byte intervals are [start, endExclusive). Empty intervals are valid where semantically meaningful. Create tested adapters for old inclusive selection/diff contracts. Reject reversed intervals, overflows, negative lengths, unsafe integer coercion, and mixing incompatible spaces.

Represent full-width target addresses, integers, and timestamps with BigInt internally or an equally exact representation. JSON uses canonical decimal strings plus explicit encoding where needed; display can use hex. Do not JSON.stringify raw BigInt. Do not use Number for u64/u128/u256 values. Do not claim all 64-bit file positions are usable in every environment.

BoundedCheckedReader must support:
  endian-specific scalars, signed/unsigned widths, exact bitfields;
  varint/LEB128 with maximum width and canonicality policy;
  checked add/multiply/range/slice with parent bounds;
  nested structures constrained to their declared containing span;
  finite recursion/node/read/allocation budgets;
  source identity checks and cancellation;
  truncated vs invalid vs unsupported vs budget-exhausted distinction.

Float values retain raw bits. NaN payloads, infinity, signed zero, rounding, and subnormals must not be erased by JSON normalization. Use tagged value representations and separate display strings from exact machine data.

Result envelope v2 concept:
  schemaVersion, operationId, operationVersion, jobId?

Paged is not truncated: a cursor can mean more recoverable results. Complete is about the declared operation subset, not proof that an artifact is secure.

05. LARGE-DATA ENGINE, SNAPSHOTS, AND EDITING
========================================================================

SOFTWARE-MUST: replace whole-file analysis paths with a bounded source architecture while preserving the small-input editor.

ByteSource contract:
  known size or an explicitly different streaming-source type;
  bounded random read; async chunk iteration; idempotent close;
  cancellation before and after I/O; closed-state checks;
  immutable snapshot identity or an explicit mutable-source policy;
  exact read completion with short-read retry and true EOF handling.

Chunk iterators validate start/end/chunkSize before iteration, including empty ranges. chunkSize must be a positive safe integer and fit the operation budget. Reading length zero is defined. Tests must cover pre-aborted signals, abort after a completed OS read, close twice, read after close, truncation, and failed open cleanup.

Source implementations:
  memory source owns its immutable content or exposes clearly labeled ownership transfer;
  Blob source reads slices; Node source reads through open handles;
  slice source maps a parent span;
  concatenated/segmented source maps several parents with missing spans explicit;
  overlay source supports sparse replacements and insert/delete pieces;
  generated sparse source for large deterministic tests without allocating the file;
  transformed source has mapping metadata and materialization/checkpoint policy.

Do not treat mtime+size as a cryptographic identity. Open first and derive metadata from the opened handle. Provide at least:
  1. pinned snapshot: content-addressed project copy made atomically and validated;
  2. reference mode: opened source with before/after checks, clearly weaker against concurrent same-size modification.
Hash-verified evidence requires a consistent snapshot. Metadata checks alone cannot prove race-free immutability. If a strong snapshot cannot be established, report that limit or refuse the strong verification claim.

Default proposed budgets, centralized and adjustable with upper-bound validation:
  I/O chunks: 1 MiB
  browser byte cache: 32 MiB
  normal worker analysis working set target: 64 MiB, excluding source Blob backing storage
  MCP raw read: maximum 64 KiB of raw bytes; account for hex/JSON expansion separately
  MCP serialized result: maximum 256 KiB; page before this limit
  search/string page: maximum 1,000 items with a separate byte budget
  interactive parser nodes: maximum 50,000 per materialized page/tree budget
  parser nesting: maximum 64 unless a validated profile explicitly lowers/raises it
  worker parallelism: at most 2 heavy jobs by default
  jobs have explicit wall-time, output, temporary storage, and cancellation budgets

These are initial engineering settings, not measured achievements. Tune only with recorded measurements. Enforce actual allocations and output counts; a config field that nobody checks is not a resource limit.

Use LRU/window caches with source revision in keys. Prevent concurrent read amplification and cache stampedes. Reject stale worker responses after document switch or revision change. Transfer buffer ownership deliberately; never detach an in-use editor buffer. SharedArrayBuffer must not be a requirement for basic operation.

Editing:
  use a persistent piece table/rope or equivalent bounded overlay;
  store edits and inverse operations, not whole-file copies per keystroke;
  group transactions; invalidate affected caches; new edit after undo discards redo branch;
  retain inserted bytes subject to quota; source revision anchors history;
  include insert/delete/replace semantics independently from existing offset patch semantics;
  full text input editor stays bounded and explicit; viewing a 1 GiB file must not format 1 GiB as a giant hex string;
  export streams pieces to output; verify digest where requested;
  browser streaming-save support is feature-detected; bounded Blob fallback must disclose its size cap.

Do not claim an insert/delete edit is representable by the old offset-aligned patch unless the format actually supports it. Keep existing patch versions stable; introduce a separately versioned edit/recipe contract when required.

========================================================================

SOFTWARE-MUST:

  masked hex/text search; ASCII/UTF-8/UTF-16 extraction;
  offset-aligned diff with paged runs; multi-dump XOR/bit variability;

Search:
  handle matches spanning chunk boundaries without duplicates;
  define overlapping matches, empty patterns, wildcards, text encoding, and search span;
  carry only necessary overlap/state; limit pattern length and compile cost;
  cursor binds operation+parameters+snapshot+next position;
  stale cursor returns an explicit stale-source/invalid-cursor result;

Strings:

  moved/duplicate structures produce ambiguous matches rather than invented identity;
  never promise a global minimum binary edit sequence for large arbitrary files.

Transforms:
  slice, concatenate, deinterleave, byteswap, bit permutation, XOR mask, OOB separation;
  each declares reversibility, parameters, affected spans, and mapping precision;
  chunk-dependent transforms must carry phase/alignment across chunks;
  compression/decompression requires streaming output quotas, ratio limits, nesting budgets;
  decompression maps output to a compressed input region unless exact mapping is available.

  ECC correction: a new candidate plus corrected-bit ledger and codeword dependencies;

  reject derivation cycles; bound traversal; distinguish relation graphs from derivation DAG;
  canonical node payload hashing excludes volatile timestamps/absolute machine paths;
  project indexes are rebuildable from committed manifests;
  edits invalidate dependent results or leave them attached to the prior snapshot;
  redaction produces a separate export graph with declared omitted nodes.

Uncertainty model:
  observed; derived-deterministic; inferred; externally-reported; unknown;
  exact/region-only mapping precision;
  valid/corrected-candidate/uncorrectable/truncated/missing data quality;
  candidate alternatives and supporting/contradicting evidence;
  confidence labels tied to a method, not unexplained decimal probabilities.

A majority vote is not proof of the original bit. ECC decoder success is not an unlimited guarantee of original data, especially beyond its correction assumptions. Rechecking parity is necessary but cannot exclude every possible miscorrection. Preserve candidates and external validation status. Entropy is not proof of encryption. Correlation is not proof of causation. A trace missing an event cannot prove it never occurred without coverage guarantees.

Represent missing bytes with an explicit sparse/validity structure; do not silently fill with zero/0xff and call it observed data. Materializing with fill bytes is a separate, recorded export policy. New unknown information never disappears because a downstream parser returned "valid".

09. FORMAT REGISTRY, PARSERS, AND STRUCTURAL REASONING
========================================================================

SOFTWARE-MUST: versioned parser registry and real bounded parsers for the declared initial subsets. Parse metadata lazily; do not allocate a complete decompressed filesystem to display a header.

Registry contract:
  id/version; spec revision/reference; license; detection strategy;
  supported variants; maximum lookahead; reader dependencies;
  parse root; expand child page; validate rules; optional mapping/export;
  no-match vs recognized-but-invalid vs recognized-but-unsupported.

Detection may return multiple candidates. A magic signature is a hint. A parser failure must not be hidden by falling through to a false confident label. Do not parse every format over the full input just to identify it.

Shared field contract extends existing StructureField with:
  stable field path scoped to snapshot/parser version;
  exact typed value and bounded display;

  interpretation provenance and spec reference;
  status independent from children and document completeness.

Mandatory format subsets:
  F01. Preserve ELF and PNG behavior; migrate to bounded reads. ELF supports current class/endian combinations, section/program tables and bounded symbol/relocation/dynamic metadata expansion. Unsupported machine-specific relocation semantics remain explicit. PNG validates chunk lengths/CRC without decoding the image by default.
  F02. PE/COFF: DOS/PE signatures, file/optional headers, sections, data directories, bounded imports/exports and RVA mapping. Treat PE32 and PE32+ separately. File-backed extent, memory zero-fill, overlay bytes, and unmapped ranges are different. Signature/certificate presence is not trust verification. Use Microsoft's PE reference [S04].
  F03. WebAssembly binary: magic/version, section framing, bounded LEB128 and basic type/function/import/export/code metadata. Unsupported proposals are explicit. Structural parsing is not full validation or execution.
  F04. ZIP central/local metadata with bounded ZIP64 where implemented, mismatch diagnostics, no automatic extraction, no guessing encrypted contents. Handle descriptors and overlapping entries conservatively. Payload extraction requires output quotas and path policy.
  F05. GPT/MBR: headers/entries, checksums where defined, logical block size parameter, primary/backup disagreement. Do not assume sector size from file size alone.
  F06. UBI: eraseblock headers, IDs, sequence/volume mapping metadata and checksums under a pinned supported subset. Preserve multiple candidate versions. Filesystem mount semantics are outside a header parser.
  F07. SquashFS metadata inspection plus one declared decompression/regular-file extraction subset validated against a maintained reference tool. Add JFFS2/UBIFS header/node inspectors with explicit limits; full reconstruction remains profile/format dependent and must not be claimed from signature recognition.
  F08. SafeTensors plus ONNX metadata as described in section 16.
  F09. Bitcoin transaction/CompactSize and Ethereum RLP byte structures as described in section 15.
  F10. Custom schema v2: bounded nested structures, arrays/count references, typed bitfields, checked relative offsets, tagged variants, endian overrides, derived assertions, and lazy expansion.

Custom schema execution is a declarative interpreter. No eval(), new Function(), arbitrary JS, dynamic imports, unrestricted regex evaluation, arbitrary recursion, or filesystem/network access. Expression operations are allowlisted typed AST nodes with fuel/width limits. Reject cycles, unknown references, overflow, duplicate IDs, parent-bound escape, and counts that exceed budgets. User-supplied schema text is data.

Kaitai interoperability is an adapter/translation subset, not a full compiler rewrite. If implemented, document supported constructs, preserve source spans where available, and reject unsupported expressions honestly. Reference [S12].

Rule diagnostics:
  rule ID/version, severity as structural diagnostic, expected/actual;
  source spans and related fields; spec link; evidence IDs;
  no automatic CVE/severity/exploitability assertion.

Required structural checks include overflow-safe lengths, containment, overlaps, alignment, missing required fields, contradictory counts, checksum mismatch, unexpected trailing data, and invalid discriminants. Overlap is only suspicious where the format forbids it; overlapping views can be intentional.

  symbols and labels are optional, separately sourced;
  RISC-V/ARM32 and additional ISAs are added through the same registry with fixture validation.

  import compiler diagnostics, optimization records, LLVM IR text and debug associations under pinned formats;

  build configuration includes compiler version/flags/target triple and artifact hashes;
  do not derive source-level causation from a decompiler guess;
  use LLVM language semantics as a versioned reference [S03], not a claim that all IR is supported.

  raw regions with base address, permissions if known, acquisition provenance;
  import one real ELF core subset and one documented Windows minidump subset or a maintained parser adapter;
  threads, registers, module list and memory ranges with explicit absent sections;
  bounded pointer scan configured for width/endian/alignment/range;
  a pointer-shaped value is a candidate reference, not proof of an object;
  holes remain missing, not zero;
  UAF/race claims require temporal/allocator/sanitizer evidence beyond a static dump.

Page table/MMIO research:
  generic hierarchical address translator with explicit architecture profile;
  one testable reference paging profile with canonicality, level, page-size, permissions, and reserved-bit rules pinned to primary documentation;
  optional stage-2/IOMMU support only for implemented profiles;

ExperimentSpec includes:

Mutators:

  repair a supported checksum/length only as a separate logged step;
  deterministic seeds, budgeted mutations, preserve original artifact;

Differential testing:
  two version-pinned implementations/configurations;

  nondeterministic fields removed only by explicit documented normalization;
  log both raw outputs plus normalized comparison;
  difference is an observation until its relevance to a specification is assessed.

Fuzzer adapter:
  integrate one established coverage-guided runner when installed;
  parse coverage/corpus/artifact reports without conflating instrumentation types;

13. RAW NAND, ECC, AND STORAGE RECONSTRUCTION
========================================================================

SOFTWARE-MUST: raw dump import, configurable geometry, page/OOB/block viewer, multi-read comparison, profile validation, mapping, one rigorously tested ECC reference codec.
PROFILE-DEPENDENT: real chip/controller OOB layouts, scrambling, BCH/LDPC variants, FTL reconstruction, live readers.

Profile schema:
  profile ID/version/digest; manufacturer/model identifiers only if known;
  source kind: raw physical dump | logical controller export | synthetic;
  data bytes/page, OOB bytes/page, pages/block, blocks/LUN, LUN count;
  bus width and dump byte order; plane/interleave layout when known;
  bad-block marker positions AND applicable page numbers/conditions;
  ECC step size, covered spans, parity placement, bit/byte ordering;
  polynomial/code parameters if relevant, erased-page rules;
  scrambling/interleaving pipeline with explicit parameters/order;
  source documentation, reference vectors, verification scope.

Do not infer factory vs runtime bad blocks solely from a non-0xff marker. Do not delete bad blocks from physical coordinates. Logical reconstruction may skip/remap them only through an explicit mapping step. Chip arrays need explicit ordering; do not assume dump length uniquely determines geometry.

Reference profile:
  include a clearly named synthetic laboratory profile (for example 512 data bytes + 16 OOB bytes, 32 pages/block) with completely specified metadata/ECC placement;
  this is a test fixture profile, not a manufacturer compatibility claim;
  include at least one documented real-layout import profile if authoritative specifications and redistributable/reference samples are available;
  lack of real samples does not block generic geometry/viewer/software tests, but hardware-verified support remains false.

NAND navigation:
  chip/LUN/block/page/column to raw dump offset and back;
  side-by-side data and OOB, partial-page diagnostics, page status map;
  bit variability and comparison across two or more acquisitions;
  read configuration includes reader/model/version, command/mode if known, timestamp, sample source, OOB handling, and transformations already applied by reader;
  when a reader silently corrects ECC, retain that acquisition fact; do not call it an untouched raw physical dump.

ECC reference implementation:
  one fully specified Hamming/SECDED reference code, pinned bit ordering and parity layout;
  encode/check/decode separated; preserve input; corrections form a new derived candidate;
  independent published vectors or independently generated reference implementation, not only encode/decode round trips from the same code;
  test exhaustive single-bit positions for bounded codewords and representative multi-bit errors;
  state guaranteed detection/correction assumptions precisely;
  distinguish clean, corrected candidate, detected uncorrectable, unsupported layout, missing parity, and erased-page policy;
  correction ledger records every modified bit and originating codeword/parity;
  recheck parity plus independent fixture hash where available; parity consistency alone is not proof of original data.

BCH/LDPC and scrambling:
  interface supports versioned codecs; no guessed universal BCH parameters;
  use a maintained compatible implementation or verified codec with correct shortened-code and packing rules;
  LDPC cannot be reduced to a generic hard-bit "repair" function when decoder information is unavailable;
  descrambling is not decryption and ECC order relative to scrambling is profile-specific;
  unsupported codes/layouts return a reason without rewriting bytes.

Reconstruction:
  page concatenation/data-only extraction is explicitly distinct from FTL recovery;
  one fully documented synthetic mapping format for deterministic reconstruction tests;
  real mappings require specific controller metadata and handling of sequence/wrap/conflicts/stale pages;
  output holes, alternative page choices, unsupported metadata and uncertainty retained;
  eMMC/UFS/SSD logical exports must not be presented as raw NAND geometry;
  encryption keys are never guessed or sent to cloud services.

Primary NAND terminology/reference: Linux MTD documentation [S01]. Pin relevant upstream source or manufacturer specifications for actual layouts; that general document does not establish every device's format.

21. PATCH, RECIPE, AND EVIDENCE CONTRACT MIGRATION
========================================================================

SOFTWARE-MUST: resolve actual schema/runtime drift before adding more consumers.

Patch audit procedure:
  collect existing code-generated v1, published-schema v1, and published v2 examples;
  list each dialect's exact semantics and supported operations;
  freeze regression fixtures for existing valid behavior;
  implement explicit dialect detection or reject ambiguity;
  choose a canonical internal model with adapters;
  maintain v1 read compatibility for genuine prior outputs;
  implement published v2 correctly, or if ambiguous define a new version and accurate compatibility documentation;
  do not mutate published version meaning silently;
  add generated schema/examples/validator conformance tests.

Patch application:
  validate entire patch/resource bounds first;
  verify source identity and preconditions against pinned source;
  stage output without mutating source;
  verify expected target length/hash;
  commit output atomically where platform guarantees allow;
  fail-if-exists unless explicit output replacement is requested;
  handle target/source same identity, overlaps, out-of-order operations, truncation, extension and empty files according to contract;
  cleanup only staging files owned by the job;
  distinguish atomic visibility from crash durability; use fsync/rename strategy where supported and document filesystem limits.

Recipes:
  preserve old pure recipe behavior via compatibility layer;
  v2 is a versioned DAG of allowlisted operations/artifact inputs;
  exact input hashes, operation/profile versions, expected outputs and budgets;
  reject cycles, missing dependencies, duplicate IDs, invalid schemas and unsupported operations;
  pure replay cannot spawn a process or operate hardware;
  experiment steps belong to an explicitly effectful runner contract;
  cache keys include input/version/parameter identity;
  deterministic replay comparison excludes timestamps and environment path labels;
  cancellation never publishes a final artifact as complete.

Evidence bundle:
  manifest, public/private metadata separation, artifact hashes/lengths;
  findings with exact byte/address/trace references;
  operation chain, profiles/spec revisions, expected versus actual;
  oracle, reproduction command, tool versions, environment requirements;
  tests actually performed and known limits;
  optional source binaries controlled by export policy;
  original logs are referenced with redaction status;
  no automatic upload, email or bounty submission.

Verification levels are separate:
  integrity: included bytes match manifest;
  structural: schemas/dependencies/relationships are valid;
  replay: deterministic operations reproduce expected results;
  experimental: target behavior reproduces under stated environment;
  hardware: a separately recorded physical acquisition/experiment was validated.

Hashing is not proof of authorship. A signed manifest is not proof the conclusion is true. A report with redacted required inputs may be integrity-verifiable but not replayable; display this explicitly.

Redaction:
  policy-based projection of ALL nested data, labels, filenames, strings, raw hex, logs, notes and recipes;
  configurable omission of hashes because hashes can identify known sensitive content;
  tests plant sentinel secrets in nested arrays/objects/logs and require no unredacted export leak;
  Markdown/HTML/terminal injection-safe formatting;
  preserve original private project; redacted export is a new artifact;
  record what was omitted and which replay checks become unavailable.

Research report template:
  title; affected local component/build; authorized scope reference supplied by researcher;
  observation; expected/actual; reproducible steps; minimal input;
  evidence links; root-cause hypothesis versus confirmed cause;
  demonstrated impact; untested impact explicitly excluded;
  possible remediation/regression test where supported;
  limitations and disclosure metadata.

Use official Google/Microsoft program pages only as pointers to current scope [S14][S15]. Do not hardcode a company's entire product catalog as authorized. A report template does not certify bounty eligibility.

Example tensor bounds invariant for a nonempty strided tensor:
  byte address = storageBase + storageOffset + sum(index_i * byteStride_i)
  extrema are computed with exact integers over each dimension's legal index interval;
  include element storage width in the final half-open accessed span;
  shape dimensions of zero yield no accesses, before evaluating dimension-minus-one;
  distinguish bit-stride descriptors from byte-stride descriptors;
  an enclosing span may contain holes and must not be mistaken for every byte being accessed.

  re-running a pure operation can yield the same content ID but a new event ID;

31. DECISION RULES FOR TRADEOFFS AND UNKNOWN DETAILS
========================================================================

When you face a choice, apply these priorities in order:
  1. Correct bytes/semantics and preservation of original evidence.
  2. Bounded resources, isolation claims that match reality, no implicit external effects.
  3. Reproducibility and truthful capability status.
  4. Existing user workflow compatibility.
  5. Cross-surface consistency and maintainable extension points.
  6. Measured performance.
  7. Visual polish and convenience.

Examples:
  Unknown NAND layout -> show raw geometry/candidates, do not invent ECC.
  Unsupported model dtype -> metadata plus unsupported status, do not reinterpret as f32.
  No GPU -> implement/import/test fixtures; report live GPU integration unavailable.
  No sandbox -> keep offline analysis working; refuse untrusted native execution on an unrestricted fallback.
  Browser export API missing -> offer bounded compatible export with a stated limit.
  Huge format child count -> page children or return a bounded partial parse, never allocate all.
  Ambiguous patch dialect -> reject or require explicit dialect, never silently choose dangerous semantics.
  Unknown virtual mapping -> retain address-space-qualified unknown rather than guessing file offset.
  Test cannot be run -> report not-run, command and reason; never say passed.
  All formats requested -> prioritize the specified working subsets and registry; do not put unsupported names in the ready list.

Do not add a cloud backend, account system, collaborative SaaS, marketplace, payment system, generic chat UI, or new branding as a shortcut to looking like a platform. The requested value is technical investigation depth.
