1. TYPES & CONTRACTS:
```typescript
export interface TaintSource {
  type: 'REGISTER' | 'STACK_OFFSET'
  identifier: string // e.g. "rdi", "rsi", "x0", "rsp+8"
}

export interface TaintTraceStep {
  offset: number
  mnemonic: string
  operands?: string
  taintedInputs: string[]
  taintedOutputs: string[]
  violation?: {
    type: 'BRANCH_DEPENDENCY' | 'INDEXED_MEMORY_LEAK' | 'VARIABLE_LATENCY'
    severity: HazardSeverity
    reason: string
  }
}

export interface TaintAuditOptions {
  baseAddress?: bigint | number
  stopOnFirstViolation?: boolean
  trackMemoryTaints?: boolean
}

export interface TaintAuditResult {
  isProvablyConstantTime: boolean
  hasViolations: boolean
  activeTaints: string[]
  trace: TaintTraceStep[]
  violations: AuditHazard[]
}
```

2. FORWARD PROPAGATION RULES (x86_64 & AArch64):

A. Register Normalization & Aliasing:
- x86_64 64-bit/32-bit/16-bit/8-bit register alias mapping:
  * `rax`, `eax`, `ax`, `al`, `ah` -> map to canonical root register `rax`.
  * `rbx`, `ebx`, `bx`, `bl`, `bh` -> canonical `rbx`.
  * `rcx`, `ecx`, `cx`, `cl`, `ch` -> canonical `rcx`.
  * `rdx`, `edx`, `dx`, `dl`, `dh` -> canonical `rdx`.
  * `rsi`, `esi`, `si`, `sil` -> canonical `rsi`.
  * `rdi`, `edi`, `di`, `dil` -> canonical `rdi`.
  * `rbp`, `ebp`, `bp`, `bpl` -> canonical `rbp`.
  * `rsp`, `esp`, `sp`, `spl` -> canonical `rsp`.
  * `r8` through `r15` (with `d`, `w`, `b` suffixes) -> canonical `r8`..`r15`.
- AArch64 register alias mapping:
  * `w0`-`w30` -> canonical `x0`-`x30`.
  * `sp`, `wsp` -> canonical `sp`.
- Flag registers:
  * x86_64: `rflags` (specifically CF, ZF, SF, OF).
  * AArch64: `nzcv`.

B. Taint Invalidation / Zeroization (Self-Clearing):
- If destination and source are identical in clearing patterns:
  * `xor reg, reg`, `sub reg, reg`, `pxor reg, reg`, `eor reg, reg, reg`:
    -> MUST REMOVE taint from `reg`. The register is now provably ZERO (clean).
  * `mov reg, 0`, `mov reg, 0x0`:
    -> MUST REMOVE taint from `reg`.

C. Taint Propagation (Data-Flow):
- Transfer operations:
  * `mov dst, src`, `movzx dst, src`, `movsx dst, src`, `ldr dst, [src]`:
    If `src` is tainted, `dst` becomes tainted. If `src` is clean, `dst` becomes clean.
  * `xchg op1, op2`: swap taint states between `op1` and `op2`.
- Arithmetic & Logical operations:
  * `add dst, src`, `sub dst, src`, `adc dst, src`, `sbb dst, src`, `or dst, src`,
    `and dst, src`, `xor dst, src` (when dst != src), `lea dst, [src1 + src2]`:
    If ANY input operand is tainted:
    1. Destination register `dst` becomes tainted.
    2. Flag register (`rflags` / `nzcv`) becomes tainted.
- Comparisons & Test operations:
  * `cmp op1, op2`, `test op1, op2`, `subs ...`, `tst ...`:
    If either `op1` or `op2` is tainted:
    -> Flag register (`rflags` / `nzcv`) becomes tainted.

D. Non-Interference Invariant Checks (Violations):
- CRITICAL: Secret-Dependent Control Flow (Branch Hazard):
  * When executing any conditional jump (`X86_BRANCHES` or `ARM_BRANCHES`):
    If `rflags` or `nzcv` is tainted -> FLAG CRITICAL VIOLATION:
    `"Conditional branch depends on secret-tainted flags; violates constant-time non-interference."`
  * For AArch64 `cbz reg`, `cbnz reg`, `tbz reg`, `tbnz reg`:
    If `reg` is tainted -> FLAG CRITICAL VIOLATION:
    `"Direct register test branch depends on secret-tainted register."`

- CRITICAL: Secret-Dependent Memory Addressing (Cache-Timing Hazard):
  * In any memory operand `[...]`:
    If ANY register inside the brackets is tainted:
    Exception: stack access `[rsp + const]` or `[rbp - const]` where only the offset is constant
    is allowed IF the stack base itself isn't tainted.
    If an index register or dynamic base register is tainted:
    -> FLAG CRITICAL VIOLATION:
    `"Memory address calculation uses secret-tainted register; causes cache-timing side-channel."`

- HIGH: Variable-Latency Arithmetic:
  * `div`, `idiv`, `udiv`, `sdiv` where operand is tainted.
  * Shift instructions where shift count register (`%cl` / variable) is tainted.

E. Clean Verification (`isProvablyConstantTime`):
- If all instructions in the selected sequence execute without triggering any of the
  above invariant violations, set `isProvablyConstantTime: true` and `hasViolations: false`.
